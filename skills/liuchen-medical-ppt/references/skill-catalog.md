# 完整技能清单与调用链

本文件是综合工作流的技能目录。创建本技能时用户要求将前序科研PPT工作涉及的文献、互联网、制作、可编辑重建和提问技能明确纳入。加载本目录后，仅阅读本次需要的技能正文；每个技能的当前本机说明决定其具体工具契约。

## 一、前序对话明确点名的核心技能

| 环节 | 技能名称 | 具体职责 | 与其他技能的衔接 |
|---|---|---|---|
| 文献检索 | `academic-search` | PubMed/PMC等论文检索、DOI及作者元数据、开放全文获取、论文记录核验去重 | 输出可追溯论文清单给全文阅读和逐页证据表 |
| 互联网搜索 | `agent-reach` | 网页、学术机构信息与相关平台资料获取；按其路由选择后端 | 论文问题优先专门学术检索；网页内容须核对原页面 |
| GPT Image课件制作 | `codex-ppt` | 大纲、风格、样张、页面生成、生成状态与PPT组装 | 原图不变时用混合制作安排；不能把生成的科研图当原图 |
| 图片PPT转可编辑 | `image-to-editable-ppt` | OCR、页面分解、原生文本与形状重建、前景/背景分层、记录和最终验证 | `presentations`负责回装整稿、保留页与媒体核验 |
| 逐页提问 | `grill-me` | 对`grilling`的简短入口，逐页讨论内容及布局选择 | 先有具体逐页草案，再问用户 |
| 带文档的审问 | `grill-with-docs` | 组合`grilling`与`domain-modeling`，使讨论、术语和决定落地 | DOCX修订/批注读取另由`documents`承担 |

以上均为用户在前序对话明确指定过的名称。下列技能是综合工作流的配套或可选补充；不要将它们全部说成用户曾点名调用过。

## 二、文献阅读、证据综合与科研素材

| 技能 | 使用条件 | 产物/边界 |
|---|---|---|
| `academic-search` | 找论文、核对作者角色/年份/DOI、获取开放全文 | 检索记录、论文元数据、全文来源；不是泛网页素材搜索的统一替代 |
| `academic-research-suite` | 需要深度文献综述、证据综合、研究设计或统计解释 | 证据组织与研究问题分析；普通单页核对不必加载整套流程 |
| `pdf` | 阅读论文正文、图注、补充材料，提取或检查原图 | 实际阅读全文相关部分、页面/图号对应与高质量素材；来源是本机当前`pdf:pdf`技能 |
| `paper2skill` | 多篇全文要转为可复用、经核验的论文知识包 | 可选持久资料层；不为一次小改动额外运行 |

论文事实以正式正文、图注及作者脚注为准；简历用于发现线索。IF与分区需年份/版本，不把搜索结果片段当正式核验。

## 三、互联网资料与来源调研

| 技能 | 使用条件 | 产物/边界 |
|---|---|---|
| `agent-reach` | 公开网页、医院/期刊/会议资料、平台内容或一般互联网检索 | 可追溯页面内容，遵循其平台路由；其已明确要求优先专用平台技能时照办 |
| `research` | 围绕一个具体问题调查高可信一手来源并留存结论 | 有来源的研究笔记；可选，不是每次搜索都加一轮研究 |
| `computer-use` | 必须实际操作浏览器/网站界面，API无法完成所需步骤 | 浏览与下载操作；先读当前本机技能，遵守工具能力和网站访问限制 |

`agent-reach`在`.codex/skills`和`.agents/skills`可能各有一份，优先当前会话指定入口；只加载一个实际适用版本，避免重复执行。浏览器工具、网页搜索工具是运行工具，不另宣称为已安装技能。

## 四、PPT制作、图像生成与模板

| 技能 | 使用条件 | 产物/边界 |
|---|---|---|
| `presentations` | 读取旧稿、原生文本/形状编辑、精准复制换页、合并、备注与媒体保留 | 可编辑`.pptx`及渲染检查；本机当前入口名可能显示为`presentations:Presentations` |
| `codex-ppt` | 用户选择GPT Image视觉生成路径 | 统一视觉、样张和生成页面；其整页栅格输出不等于对象可编辑 |
| `imagegen` | 背景、概念插图、示意图或图像编辑 | 独立图像资产；本机入口为系统`imagegen`，不重绘真实科研数据 |
| `markdown-ppt-toolkit` | 输入以Markdown为主，需要Slidev/Marp或网页演讲 | 可选替代制作分支；精确Office版式与视频保留优先`presentations` |
| `template-creator` | 用户明确希望保存样张风格为可复用个人模板 | 可选模板技能；入口为当前插件`template-creator:template-creator` |

**模式由交付决定**：原生可编辑优先`presentations`；GPT Image视觉生成用`codex-ppt`/`imagegen`；已有整页图像要可编辑才进入`image-to-editable-ppt`。不得强制每份课件走“生成整页图片→OCR重建”一圈。

## 五、可编辑还原与原稿保护

| 技能 | 使用条件 | 必要保留 |
|---|---|---|
| `image-to-editable-ppt` | 图片版PPT、扫描页、PDF页或截图重建 | 原生文本、主要形状、独立图标与背景，科研原图作为独立数据图保留 |
| `presentations` | 将指定页重建结果回装旧稿，或原生页直接编辑 | 非目标页、备注、科研媒体、病例视频、页序与播放关系 |

PaddleOCR是`image-to-editable-ppt`使用的识别服务/运行配置，**不是另一个技能**。PowerPoint、LibreOffice、editppt、图像生成后端也分别是工具、程序或服务。技能清单与运行依赖分别记录。

## 六、逐页提问与文档决策

| 技能 | 职责 |
|---|---|
| `grill-me` | 用户面对的简洁审问入口，底层使用`grilling` |
| `grilling` | 决策树、依赖前沿、分轮问题与等待用户决定 |
| `grill-with-docs` | `grilling`＋`domain-modeling`的文档化入口 |
| `domain-modeling` | 精确术语和边界，按需保存术语表与重要决定 |
| `to-questionnaire` | 向学生或合作者收集用户无法独立确认的信息，生成问卷，不自动发送 |

默认逐页覆盖，每页有审阅状态。根据当前材料选择一个入口，不把多个审问技能对同一页重复执行。具体规则见[逐页提问](page-interview.md)。

## 七、Word、演讲稿与个人语气

| 技能 | 职责 |
|---|---|
| `documents` | 图文大纲Word、表格脚本、真实修订、批注落实与文档渲染；入口为当前`documents:documents` |
| `academic-humanizer` | 学术表达清晰度与证据措辞，保留数字、引用和结果 |
| `humanizer` | 去掉空泛、机械和套话，转为自然口述；不删除必要科学边界 |
| `write-like-me` | 根据用户真实文字样本匹配刘晨的讲述风格，不编造经历；入口为当前`write-like-me:write-like-me` |
| `presentations` | 将已确认演讲稿按实际页序写入备注，核对画面与讲稿一致 |

## 八、默认组合调用顺序

### 从论文和旧课件新建/整合

`presentations`＋`documents`盘点 → `academic-search`＋`pdf`核验 → 需要时`agent-reach`补充网页 → 逐页图文草案 → `grill-with-docs`或`grill-me`审阅 → 用户确认 → `presentations`原生制作，或选定`codex-ppt`/`imagegen`视觉分支 → 备注与验收。

### 图片课件变可编辑

`presentations`明确指定页及保留项 → `image-to-editable-ppt`按OCR和页面状态流程重建 → `presentations`回装 → 原生对象、媒体、备注及渲染验收。内容不变时不启动新的文献综述或整套大纲审问。

### 精简或打磨讲稿

`presentations`读实际页与备注 → 必要的`pdf`/`academic-search`核对 → 逐页草案和`grill-me`取舍 → 用户确认 → `academic-humanizer`/`humanizer`/`write-like-me`按实际需要润色 → 写备注；要求同步Word则加`documents`真实修订。

### 仅修改风格

`presentations`读目标页与批准样张 → 准备每页布局 → 有选择需决定时`grill-me` → 选定的原生或GPT Image路径制作 → 局部视觉与保护项验收。科学内容不变时，不自动把全部论文重新检索一遍。

## 九、加载和授权

用户无需逐个输入技能名：执行综合工作流时按上述条件读取所需技能并执行。遇显式调用入口或运行环境差异，遵循当前技能配置，不虚构不可调用的工具。此目录不授权额外安装、传输无关文件、发邮件、投稿或对外发布。新增依赖或缺少关键技能时先说明影响，保持其他已授权步骤可继续。
